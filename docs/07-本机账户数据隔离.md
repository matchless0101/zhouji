# 本机账户数据隔离

2026-09-13：在现有登录、本机备份基础上增加独立存储。此阶段只隔离设备上的数据，不上传任务、目标或计时，不代表已完成云同步阶段 B 的服务端协议。

## 用户行为

| 操作 | 结果 |
| --- | --- |
| 升级旧版本 | 原数据库继续作为“游客记录”，即使此前已登录也不自动认领旧数据 |
| 登录账户 | 打开该账户的本机记录；首次为空，之前的游客记录仍保留。提示未自动合并或上传 |
| 查看游客记录 | 在“我的”切换；登录身份保持不变，新内容只写入游客记录 |
| 返回账户记录 | 在“我的”打开当前已登录账户的记录；不会合并游客内容 |
| 退出登录 | 返回游客记录；账户数据独立保留，重新登录原账户后可打开 |
| 登录另一账户 | 列表、统计、计时、备份及恢复预览均使用另一份存储；不复用上一账户记录 |
| 登录过期或授权撤销 | 清除登录身份，当前账户缓存仍属于原账户，可离线使用并显示重新登录提示；不自动转为游客数据 |
| 切换会改变数据范围且存在运行或暂停计时 | 提示先结束，取消切换；原计时与原数据不动 |
| 打开存储或保存失败 | 不切换、不清空旧库；显示重试提示。启动时找不到之前选中的账户库，也不会用空库冒充恢复成功 |
| 注销账户 | 先保存该账户的本机 JSON 副本，再请求服务端注销；成功后返回游客记录，可“导出注销前备份” |

注销前备份保存失败时不发送注销请求；服务端注销失败时继续保留账户状态供重试。注销副本与恢复保护副本分别保存；“导出注销前备份”只展示最近一次注销的副本入口。导出的文件仍标记原归属，当前不支持恢复到另一账户；可自行保存和读取 JSON，后续跨账户导入须独立实现。旧账户本机文件不自动删除，也不暴露在新账户普通页面中。

已登录时查看游客记录、或过期后使用账户缓存，页面底部都有当前数据范围提示。切换保留当前一级标签页，重建内部页面、计时对象和恢复确认，避免旧任务编辑或旧备份预览残留。

游客数据合并到账户、首次上传、换机下载、内容同步和跨账户导入仍未实现。“打开账户记录”不是“合并”或“开始同步”。

## 存储与兼容

- 原 `ModelConfiguration()` 的默认库继续使用，不复制或重命名正在打开的 SQLite 文件；没有更改现有 SwiftData 实体字段，也不把旧记录写成当前登录人的数据。
- 账户使用 `Application Support/AccountLibraries/account-<账户 ID 的 SHA-256>.store`。散列仅用于稳定文件命名与备份来源标记，不是加密或服务端权限凭证。
- 第一次离开旧游客库前保存 `before-isolation.json`，写入失败不切换。原数据库本身始终保留，运行计时亦不会在升级时被改写。
- 选中库持久化，重开继续使用；会话过期时保留账户库归属。成功退出登录则保存游客选择。
- 每个账户容器独立；目标关系、软删除历史、计时区间、统计查询和计时控制器只读取当前容器。同 ID 可以分别出现在不同账户，不能跨库去重。
- 账户备份延续 JSON v2，`dataScope` 是 `account-<散列>`；游客备份仍为 `local`，v1 缺失来源时视为游客。恢复要求文件来源与当前容器完全一致，否则在预览和写入之前拒绝。
- 恢复前保护文件也按账户分开；原游客保护文件路径保持兼容。篡改明文 JSON 标记不代表身份验证，且不能访问任何服务端资源。
- 日志、Git 和 CI 不新增真实账户 ID、第三方 AppID、会话令牌或密钥。

## 验收范围

2026-09-13 验证：64 项单元测试、3 项模拟器界面测试通过；Debug / Release 真机配置签名构建通过。未在生产执行账户注销或修改服务器配置。

自动化覆盖：旧游客库保留、A/B 同 ID 隔离、真实文件库重新读取、计时切换阻止、过期后归属保留、新库打开失败与缺失文件处理、备份及保护文件隔离、查看游客时注销仍备份原账户、钥匙串保存失败不切换、未结束计时时不发送退出请求。

界面测试使用显式开启的内存数据与模拟登录状态，验证切换后任务与统计刷新；不作为 Apple/微信真机登录或线上注销的证据。真实账户双向切换、系统在登录与保存交界处终止、低存储和真机注销导出仍须人工验收。

下一步是游客归属确认与首次同步；云同步增量中冲突、删除保留、多设备计时及跨账户导入的待确认建议仍保持待确认。

# 原微信账户补设用户名密码：交付验证

日期：2026-10-18。状态：代码完成并验证，后续用户授权继续发布；生产迁移 007、后端及隐私页部署已完成，新构建 1.0（5）已上传并完成处理，出口合规已保存。详见 [发布记录](README.md)。旧构建 1.0（4）不包含本次增量；尚未将构建 5 关联审核版本或重新送审。

## 用户行为

- 原独立微信账户可在「我的 → 偏好设置 → 账户安全 → 设置用户名和密码」自愿设置，成功后保存恢复码。
- 保持同一账户 ID、昵称、头像及本机记录库；微信继续可用，之后无需安装微信也能使用用户名密码登录原账户。不新建或合并账户。
- 首次设置要求最近 10 分钟内微信登录。用户名占用可修改重试，已设置的密码不可被此入口覆盖。设置成功后其他设备需重新登录。
- 恢复码只在内存展示，不写入钥匙串。保存新会话失败时仍保留已收到的恢复码，清除失效身份并提示重新登录；网络响应丢失时提示确认设置结果并更新恢复码。

## 验证

- iOS：129 项单元测试通过，包含同账户及记录库保持、用户名冲突、近期登录错误、钥匙串写入失败、成功响应丢失。
- iPhone 17 Pro / iOS 26.5 模拟器：3 项界面测试通过，分别为原微信账户首次设置后退出并用密码登录、未安装微信时解绑、注册登录及恢复码流程。恢复码页面断言只展示一次。
- Release 通用模拟器构建通过；发布二进制不含新增隔离测试账号、会话或测试服务。版本号仍为 1.0（4），未改发布配置。
- 后端本地：103 项通过，9 项真实 MySQL 用例按未配置环境跳过；服务器隔离 MySQL 全量运行：112 项通过。覆盖从 006 升级到 007、旧账户资料和身份保持、改密恢复解绑、失效会话、同账户并发设置及不同账户抢占同一用户名。
- 隔离数据库由测试创建并清理，未部署或更改生产账户。首次验证包缺少运维脚本导致的测试失败已补全验证包后全量重跑通过。
- 官网及关联链接：9 项测试通过。隐私页已说明原微信账户可选补设密码，已发布并核对公网摘要。
- 独立代码评审发现「钥匙串保存失败丢失恢复码」：先补测试复现，再修复并通过。界面测试发现恢复码重复展示：改由稳定的账户安全流程持有成功结果后通过。

## 发布顺序与边界

1. 获得本次部署授权后，备份生产数据库并核对当前 001–006 状态；执行一次 `server/migrations/007_wechat_password_setup.sql`。该迁移调整身份检查约束，不改写原账户 ID 或创建来源。
2. 发布后端与隐私页，使用隔离临时账户验证设置、双方式进入同一账户、恢复和清理。回退代码时保留迁移及用户新设凭据，不删除账户。
3. 上传包含本次变更的新构建，补做真实微信授权、软键盘与同账户登录验收；关联审核版本，更新审核备注和演示材料。当前模拟器的微信为隔离模拟服务，不代表真实微信授权验证。
4. 未主动设置过密码的原微信账户仍需先通过微信进入；本次不提供无微信客户端的微信授权，也不承诺 Apple 复审结果。

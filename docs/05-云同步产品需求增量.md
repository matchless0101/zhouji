## 1. 目标、范围与文档职责

用户在同一账户的设备之间获得一致的任务、目标与已保存计时记录；离线时仍可使用本机。未登录不阻止核心功能，登录成功不等于数据已经上传。同步传播误删，因此不能替代导出与灾备。

首版包含：首次归属确认、首次上传、换机恢复、增量同步、删除传播、断网重试、账户隔离、冲突处理、注销云端内容和真实同步状态。同步目标/任务/计时事实，不同步汇总统计、主题偏好、第三方头像文件或登录令牌。

首版不包含：跨登录方式账户合并、共享任务、网页编辑器、跨设备远程控制计时、自动合并重叠会话、完整历史版本/回收站界面、端到端加密、日程/标签/优先级扩展。

- [主 PRD](02-产品需求文档-PRD.md)：现有任务、目标、删除、统计规则；本文明确引用其约束。
- 本文：同步增量的规则及验收。标为“待确认”的部分只是建议；不能自行覆盖主 PRD。
- [实施路线图](03-V1-V3-实施路线图.md)：模块、协议、迁移和部署顺序，不能反向决定产品行为。
- 本文没有承诺云同步已经可用，也不作为完整隐私政策。

## 3. 数据范围、归属与迁移

### 3.1 同步什么

| 对象 | 必须保留的事实 | 不能被同步改写的口径 |
| --- | --- | --- |
| 目标 | 稳定 ID、名称、图标选择值、创建/删除时间 | 删除目标解除当前任务关系，历史目标快照不变 |
| 任务 | 稳定 ID、标题、创建/完成/删除时间、目标关系 | 恢复完成清空 completedAt；不能以“完成优先”阻止用户恢复任务 |
| 已结束计时 | 会话 ID、原任务 ID、任务/目标快照、开始/结束时间、全部有效区间 | 暂停时间不计入；历史快照不跟随当前名称变化；不能由结束时间替代区间 |
| 活跃计时提示 | 来源设备、会话/任务 ID、最近报告时间、状态 | 只是提示，过期不等于计时已停止；不得据此生成历史时长 |

累计统计继续从原始事实计算。区间需按日期/周边界求交集；由开始日期筛选会漏掉跨夜、跨周会话。云端不保存一份可独立编辑的完成数量或累计投入总量。

### 3.2 归属与同步状态分开

每条内容必须有且只有一种归属：本机游客库，或某一个粥记账户。`待上传/已同步/冲突` 是同步状态，不能代替归属字段。

- 已归属 A 的内容及其待传操作、冲突副本、下载缓存都属于 A，不能因当前登录 B 而上传到 B。
- ID 相同但账户不同，也不得跨账户查询、更新或去重。服务端以已验证登录身份确定账户，不相信请求中的 account_id。
- 当前旧版所有任务来自共享本机库，即使设备已登录，也不能仅凭当前登录状态认领全部旧记录。升级后先保留为未归属本机内容，再执行首次确认。
- 目标、任务与会话引用必须在同一归属内。历史任务或目标已软删除时，保留其事实/快照，不把会话视为损坏而丢弃。

### 3.3 升级及本机隔离

迁移前制作可恢复快照；完成迁移后核对实体 ID、数量、关系、完成/删除状态、有效区间与运行状态。失败保留原库，不用空库“修复”，不展示迁移成功。

本机账户隔离可以用独立库或严格分区实现，但产品验收一致：登录 B、退出到游客后，不能在普通列表、记录统计、计时浮条或默认导出中看到 A 的内容。其他账户缓存可保留，以便重新登录原账户恢复；不能自动转换成游客数据。

当前存在未结束计时时，首次将游客计时归属账户、切换账户或从账户库退出前提示先结束，用户可取消切换；结束与保存失败则保持原库。暂停计时仍属未结束会话，不能被悄悄带入另一账户。

## 4. 首次开启、上传与恢复

### 4.1 首次归属确认（D1/D2）

先识别当前账户及云端是否有记录，再呈现选择；不能把“保留本机”写成“云端为空”，因为云端可能已有其他设备上传的数据。

| 场景 | 行为 | 取消后的结果 |
| --- | --- | --- |
| 游客有历史，首次开启同步 | 显示当前账户昵称及登录方式、任务/目标/计时数量，选择“合并到此账户”或“暂不合并” | 未归属历史留在本机，未上传 |
| 账户云端已有数据，游客也有历史 | 清楚说明将合并两份内容，按稳定 ID/来源去重，不按同名去重 | 账户库与游客库分别保留，可进入账户库或继续本机使用 |
| 同账户已有本机归属内容 | 恢复该账户队列和游标，不再次询问是否把它当游客历史上传 | 不改变归属 |
| 本机为空、账户云端有数据 | 提示恢复数量，确认后下载；可先使用本机 | 云端不删除，不显示恢复完成 |
| 首次恢复未完成就创建任务 | 新增记录属于已选定账户，可靠保存为待同步；下载不能覆盖新增内容 | 本地新增保留 |

用户确认归属后，所有选中内容及关系原子地绑定当前账户，再进入上传队列。即使上传失败，它们也已属于该账户；不能切换 B 后再次作为游客内容认领。再次手动迁移到另一账户属于显式导入，不属于自动同步。

同名任务和目标可能有不同含义，必须保留；同一稳定 ID 的重复上传不新增第二条记录。

### 4.2 分页、失败、取消

- 首次上传/下载允许分批；仅确认已成功的批次进度，未完成批次可重试。
- 用户取消是停止后续传输，不是撤回已经上传的数据。提示“已传输部分会保留，可稍后继续”。
- 下载先保持可恢复的批次状态；当前批次关系完整、写入成功后才推进游标。中途退出、低存储或保存失败不能留下半批可见记录。
- 下载时，目标、任务、会话依赖必须能解析；被删目标按删除规则解除关系，不能使整个库不可用。
- 不要求传输期间阻塞所有编辑；本地新增修改与正在确认的批次区分。旧批次确认不能清掉发送之后的新修改。

## 5. 增量同步、离线和成功定义

### 5.1 触发与可靠性

前台进入时尝试同步；本地变更后 2 秒防抖；提供手动重试。离开前台尽力提交已持久化队列，但 iOS 可随时挂起，不承诺持续后台同步。

一次内容修改与它的待同步标记必须一起持久化。网络响应丢失、重复点击、App 被杀后重试，不能重复创建实体或重复累计会话。服务端明确确认持久化后，客户端才清理对应版本的待传标记。

登录过期时保留内容、队列和归属，暂停网络同步并提示登录；离线可使用原账户已缓存的数据。重新登录同账户可继续，登录其他账户不得复用原队列。

### 5.2 同步状态

| 状态 | 文案例子 | 判定 |
| --- | --- | --- |
| 游客/未开启 | 数据保存在本机 | 没有完成当前库的同步授权 |
| 待同步 | 有 N 项待同步 | 本地持久化但服务端尚未确认的实体变更数，不是网络请求次数 |
| 同步中 | 正在同步… | 有实际传输/应用中的批次 |
| 离线 | 暂时离线，修改已保存在本机 | 保留重试能力，不显示云端成功 |
| 登录失效 | 请重新登录后继续同步 | 不转移数据，不删除队列 |
| 需处理冲突 | 有 N 项修改需要确认 | R1 方案下存在未处理副本 |
| 失败 | 同步未完成，请重试 | 展示可理解的网络/存储/版本问题，不回显 SQL、令牌或内部路径 |
| 已同步 | 已同步 · 时间 | 本轮上行已确认，下行到已知服务器版本并在本机保存，无待传和未处理冲突 |

“已同步”只表示本机到最近完成的服务器版本，不保证未联网设备已收到数据。R3 下活跃计时旁说明“本次计时结束后同步”；不能暗示尚未结束的投入已备份。

关闭同步不改变账户归属、不删除云端或本机内容。关闭后修改仍标记为本账户本地变更，再次开启先对账；其他设备继续修改云端，因此不能按旧快照整库覆盖。

### 5.3 队列满额（R4 待确认）

5000 为压缩后的待同步实体变更数。同实体连续改名可合并为最新意图，但保留其基准版本；删除与撤销不能错误合并。达到上限时先持久化“需完整对账”标记，再允许额外本地变更，不静默丢弃。

恢复网络后使用本地脏数据与服务器版本进行完整对账，不按手机时间覆盖；对账完成前不能显示“已同步”。该路径与正常增量路径必须共用账户隔离、删除和冲突规则。若无法可靠保存内容/标记，提示保存失败并保留编辑内容，不能假称成功。

## 6. 冲突、删除和历史事实

### 6.1 冲突裁决（R1 待确认）

推荐用服务器单调版本和客户端修改所依据的基准版本识别并发。设备 createdAt/completedAt 是业务时间，不是覆盖另一设备数据的权限；系统时间回拨或大幅快进不改变冲突胜负。

| 并发场景 | 推荐结果 |
| --- | --- |
| 修改不同实体 | 分别保存，不产生无关冲突 |
| 相同基准版本，重复发送同一修改 | 返回原确认结果，不额外加版本/计数 |
| 两台设备修改同一目标/任务 | 首个合法提交形成云端当前版本；另一个本机版本保留为待处理副本，不静默丢弃 |
| 用户选择本机版本 | 基于最新云端版本重新提交；期间云端再变化则重新确认，不能绕过校验 |
| 用户选择云端版本 | 明确放弃这份冲突修改，应用云端当前版本 |
| 删除与普通编辑并发 | 删除优先；保留未提交编辑为可导出副本，不复活被删除实体 |
| 完成与恢复完成并发 | 按正常实体冲突处理，不用“已完成永远优先”取消用户恢复操作 |
| 目标已删除，旧设备仍给任务绑定该目标 | 目标保持删除，任务脱离目标，已结束会话快照不变 |

冲突入口仅在同步详情中出现，展示对象、当前值与本机修改，提供“保留本机修改/使用云端版本”。无需引入复杂版本管理界面。未处理副本持久化且可导出；不能退出或重启后消失。

### 6.2 删除与撤销（D3、R2）

保留任务现有 5 秒撤销入口。窗口内先保存本机删除及撤销状态，暂缓上传该删除；撤销后不发送已取消的删除。重启或窗口结束后补传有效删除。云端已确认的删除不能靠旧设备普通编辑复活；显式从备份恢复须作为新内容或经单独确认流程。

删除目标与解除关联任务的变更应作为一个一致的操作传递；不能只删除目标但让其他设备留着无效关系。删除不改写计时快照。

R2 建议首版保留软删除行及最小删除版本，避免历史完成统计下降，也阻止长期离线设备复活记录。30 天自动清理在确认并设计统计事实保留、删除版本保留和旧游标重建以前，不可执行。

服务器若不再保留某个旧增量游标，明确要求完整对账。客户端不能只重新上传旧库而绕过删除记录。

## 7. 多设备计时（R3 待确认）

现有单计时器限制明确为每台设备/当前库最多一条未结束会话。跨设备不强行互斥，以保留离线可用；同一任务可以产生不同会话，但绝不复制同一个会话 ID 后两端继续写。

- 只有来源设备负责本次会话。运行/暂停会话留在该设备，结束并保存后才进入内容同步。
- 其他设备只显示最后报告的活跃提示，不启动本地计时器，不据提示计算投入，不提供远程暂停、继续或结束。
- 其他设备完成或删除了本机正在计时的任务时，不通过下载自动停止/丢弃本机会话；提示任务状态已变化，保留浮条供用户结束。结束后只同步该会话事实，不能复活任务或撤销其完成状态。
- 检测到其他设备活跃时按 D7 提示，可取消或仍然开始独立会话。离线或提示过期时不宣称“没有其他设备在计时”；不保证发现所有并发计时。
- 建议活跃提示最后报告超过 15 分钟即标记过期，文案为“状态暂未更新”；此参数随 R3 一起确认。过期不自动结束原会话、不转移所有权、不产生“接管后的同一会话”。
- 不同会话即使时间重叠仍相加，首次并行提示明确这一点。不能自动取最长、并集或相互覆盖。
- 同一已结束会话重复上传相同事实应去重；同一 ID 却有不同区间/快照属于异常冲突，保留待处理数据并报错，不自行延长时长。
- 已结束区间不可相互重叠，不能为负；累计秒数须与闭合区间一致。会话结束时间不能代替实际区间。
- 设备丢失前未结束、未上传的会话不保证换机恢复；同步说明需如实陈述。

长时间未结束提醒属于另一个产品增量，本次不批准“2 小时自动截断”或修改已有投入。跨夜恢复、时间回拨依旧需要单独验收。

## 8. 导出、导入和本机恢复

现状：已有 schemaVersion=1 的 JSON 导出/导入及基础 round-trip、同 ID 更新测试；CSV 不作为恢复源。本节明确同步开放前的补充要求，不把它们全部算作当前已完成。

- 导出以固定时刻的一致快照为准，包含目标、任务、删除状态、完整会话区间和快照、格式版本及导出时间。支持导出尚未同步的修改。
- 不导出登录 token、Apple/微信凭据、数据库密码或服务端加密密钥。冲突副本与当前主版本区分，不能混成重复实体。
- 默认只导出当前选定库，不能合并不同账户缓存。账户来源只用于提示归属，不作为导入授权凭证。
- 导入先完整校验格式、版本、重复 ID、引用关系、区间、时间和数量上限；展示预计新增/覆盖/冲突数量，确认后执行。未知新版本、损坏、截断、磁盘不足或校验失败不能写入半份内容。
- 现有按 ID upsert 的语义仅限明确目标库。同步开启后任务/目标同 ID 更新应形成基于当前版本的正常本地修改，不直接覆盖云端版本或清空删除标记。已结束会话同 ID 且事实相同则跳过；事实不同时拒绝覆盖，提示冲突，不违反 R3 的会话不可变规则。
- R5 下不同账户来源先放独立本机库；用户明确导入目标账户时重建 ID 及关联，并使用导入批次标识避免重试重复导入。不根据昵称或文件中的账户 ID 认领内容。
- R5 下导出不改变现场计时；仅在备份副本中把开放区间闭合到导出时刻，恢复为暂停。导入会话与本机已有未结束会话冲突时先提示处理，保证恢复后最多一条未结束会话。
- 恢复前创建保护副本，在独立事务/临时库完成写入与统计验证；失败可恢复到导入前状态。不得删除备份中没出现的其他本机行，除非另有单独批准的“整库替换”功能。
- 本地 JSON 文件包含任务内容，分享前轻量说明文件用途及内容范围；不把普通 JSON 标成加密备份。

## 9. 注销账户与服务端恢复

### 9.1 账户注销

沿用最近 10 分钟登录与二次确认。确认文案分别说明云端删除、本机保留、第三方授权和备份保留边界；不能把退出登录称为注销。

1. 对该账户设置可靠的删除中状态，拒绝新同步写入，并撤销其其他设备会话。该操作失败可重试，不能先删除账户索引却留下无人归属的内容。
2. Apple 撤销授权；微信删除粥记保存的加密凭据，提示微信授权可在微信设置管理，不宣称已代用户撤销微信权限。
3. 删除该账户云端任务、目标、会话、同步队列、冲突副本及相关活跃提示，再完成账户删除。失败保持不可写状态并继续可重试，不显示注销完成。
4. 注销当前设备按既有规则保留本机任务，但进入明确的“本机保留副本”，与独立游客库分开；此副本不会自动归属以后登录的 B。若用户要迁移，走明确导入确认。
5. 其他设备联网得知注销后停止上传并隔离该账户缓存；离线设备无法被保证即时擦除。再次登录第三方身份若创建新粥记账户，不自动恢复已注销账户内容。

完成标准是业务数据实际不可再访问、写入或被旧设备复活，不只是接口返回成功。正常用户流程无法读取备份；备份中的历史副本按正式披露的保留策略到期销毁，不承诺即时清除全部备份。

### 9.2 备份、告警与灾备要求

正式开放同步前，批准并落地服务端备份频率、保留期、异地存储位置、加密与访问权限、允许丢失时间（RPO）和恢复时间（RTO）。这些是运维发布参数，本文不声称已有定时备份。

恢复演练在隔离环境进行，证明数据库与对应加密密钥可一起恢复；不可把生产密钥放进 Git、CI 日志或用户导出包。恢复后的数据数量、关系与统计一致。

备份回滚会回退服务器版本，必须使旧游标失效并触发重新对账，不能把“没有新变更”误判成已同步。恢复前重放备份之后的账户注销/删除记录，防止已注销账户重现；为此所需的最小删除记录、保存期限及权限必须写入运维与隐私文档。

监控至少覆盖公网健康、数据库就绪、备份任务失败与备份过期；故障通知需能到达负责人员并通过演练。当前 health 接口与一次手动备份不能代替上述能力。

## 10. 可执行验收矩阵

测试数据使用隔离账户/数据库，不对真实用户做破坏性演练。R1–R5 对应项在确认后才作为最终验收口径。

| 编号 | 前提与操作 | 必须观察到的结果 |
| --- | --- | --- |
| OWN-01 | 旧版有任务且已登录 A，升级后取消历史上传 | 旧内容完整保留、未上传，未因当前登录自动认领 |
| OWN-02 | 游客历史确认归属 A，首批上传后断网，再登录 B | 内容与剩余队列仍属 A，B 列表/统计/导出均不可见 |
| OWN-03 | 账户 B 请求读取/修改 A 的实体 ID | 服务端拒绝，不返回 A 内容，不因设备参数绕过 |
| OWN-04 | 正在运行或暂停计时时退出/换号，取消确认 | 原账户、计时、队列保持不变；保存失败也不切库 |
| INIT-01 | A 云端与游客各有同名任务，确认合并 | 不按名称去重；稳定 ID 相同的重试不新增第二条 |
| INIT-02 | 首次恢复到一半终止 App，期间有新增任务 | 重开可继续，新增任务保留，未出现断裂关系或虚假完成 |
| INC-01 | 上传成功但响应丢失，重试相同操作三次 | 只形成一次业务修改，同一会话只计一次 |
| INC-02 | 上传请求发出后继续改同一任务，旧响应随后到达 | 新修改仍待上传，不被旧响应清除 |
| INC-03 | 拉取批次写入时模拟磁盘不足 | 不推进游标，不出现半批可见数据，可重试 |
| OFF-01 | 断网编辑后重启，登录过期再登录同账户 | 编辑与队列保留，恢复同步；不会登录 B 后错传 |
| OFF-02 | 压缩后超过 5000 项再重连 | R4 下继续本地使用、触发完整对账，不丢改动、不虚报成功 |
| CON-01 | 两设备改同一任务，设备时间相差 24 小时 | R1 下按版本识别冲突，不按错误手机时间静默获胜 |
| CON-02 | 完成与恢复完成并发，用户选择恢复 | 恢复意图能提交，统计随后按 completedAt 变化 |
| CON-03 | 选择本机版本时云端又被修改 | 再次校验并提示，不盲写覆盖最新版本 |
| DEL-01 | 删除后 5 秒内撤销，再同步 | 其他设备不会收到已撤销删除；状态及关系恢复 |
| DEL-02 | A 删除任务，B 离线 60 天后提交旧编辑 | 不复活任务；历史完成数与投入按主 PRD 保留 |
| DEL-03 | 删除目标与另一设备绑定任务并发 | 目标保持删除，任务无该目标关系，历史快照不变 |
| TIME-01 | 两设备分别运行同一任务，随后各自结束上传 | 两条不同会话，区间保留，时长按 D7 相加，无会话覆盖 |
| TIME-02 | 活跃设备离线超过提示有效期，另一设备打开 | 只显示状态未知/过期，不自动结束、接管或累计远程时间 |
| TIME-03 | 相同结束会话重复上传与同 ID 异常不同内容 | 相同事实去重；异常内容报告冲突，不取最长或区间并集 |
| TIME-04 | 另一设备完成/删除当前正在计时的任务 | 本机会话可见且可结束，历史快照保留；结束上传不复活任务 |
| BACK-01 | 导出含跨夜/暂停/删除事实，再导入隔离空库 | 数量、关系、快照、各日有效投入与导出时刻一致 |
| BACK-02 | 运行计时导出，数天后导入 | R5 下恢复暂停，只算到导出时刻，无额外数天投入 |
| BACK-03 | 损坏/未来版本/非法区间/跨账户备份 | 拒绝或明确确认分库，无半写、越权或静默覆盖 |
| ACC-01 | 注销 A 时另一设备正在推送 | 删除中即拒绝写入；结束后 A 云端数据与会话不可用 |
| ACC-02 | 撤销授权/云端删除中途失败后重试 | 不提前提示成功，可靠继续，不遗留可访问的内容 |
| OPS-01 | 在隔离环境恢复较旧备份后连接旧客户端 | 重新对账，已注销账户不复活，旧游标不误判已同步 |
| UI-01 | 已登录但未上传、传输一半、离线、有冲突 | 各状态与实际一致，不显示“备份完成”或提前显示“已同步” |
| PERF-01 | 导入代表性多年历史，切换记录周期并运行计时 | 先记录耗时/内存基线；优化不得漏算跨周期区间与已删对象历史 |

全局验收还包括：深浅色、动态字体、VoiceOver、低存储、网络中断、设备时间回拨、前后台与进程终止。测试报告写明设备/系统版本、样本规模、操作及结果；单元测试通过不能代替双设备真实同步验收。

## 11. 分步交付与开放条件

每个可独立验收的功能完成后测试并单独提交、推送；不把全部同步作为一次巨大提交。以下“阶段”不要求只提交一次，具体功能各自提交。

| 阶段 | 交付物 | 开放条件 |
| --- | --- | --- |
| A 数据保护基础 | 已有 JSON 导出恢复；补 R5、持久化/迁移 fixture、CI、备份恢复及告警演练 | 当前已完成部分保留；新增行为先确认，逐项验证 |
| B 账户隔离与协议基础 | 归属迁移、本机分库/分区、服务端隔离与版本规则、幂等/游标、删除中拒绝写入 | 先通过隔离和迁移测试，不开放用户内容同步 |
| C 首次上传与换机恢复 | 明确确认、分批传输、断点续传、取消与进度 | 内部开关默认关闭，对隔离测试账户逐步验证 |
| D 增量、冲突和删除 | 正常/离线/满额对账、删除与冲突闭环、R3 结束会话同步及活跃提示 | 删除不能被旧设备复活；重试不重复计数 |
| E 注销与真实设备闭环 | 全量注销、故障恢复、双设备及辅助功能验收、隐私文案核对 | 所有发布阻断项通过后再对用户开放 |

发布阻断项：R1–R5 已确认；迁移恢复和账户隔离通过；删除与注销闭环；失败重试无丢失/重复；备份恢复与告警可执行；真实双设备测试通过；隐私政策和界面与实际行为一致。首版不承诺端到端加密，服务端可处理账户内容，隐私说明不得写成“只有你能读取”。

上架政策、素材与审核说明属于独立清单，可并行准备，但最终必须对应实际开放的功能。不因文档写完就创建云端内容表、修改线上开关或部署未经验证的同步服务。

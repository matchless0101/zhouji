# 粥记云同步产品需求增量

_定义云同步增量的产品行为、数据规则与验收标准；与 [主 PRD](02-产品需求文档-PRD.md) 冲突时，本文件对同步相关行为具最终解释力。_

> 2026-09-12 状态：用户已确认微信登录真机成功；服务端迁移 `003_wechat_login.sql` 已在生产执行。云同步尚未实现。本文档是开放云同步前的规则与验收依据，**未决规则关闭前不得进入实现**。

---

## 0. 文档目的

1. 在写代码前固定同步、删除、冲突、多设备与账户边界。
2. 把需要产品决策的问题集中列出，避免实现中临场拍板。
3. 给出可验收的完成定义，支持「一个功能完成、验证后单独提交」。

**原则**：同步是多设备一致性的能力，**不是备份**。误删会同步到所有设备；导出/导入与服务端备份仍不可省略。

## 1. 范围

### 1.1 本增量包含

| 能力 | 说明 |
| --- | --- |
| 云端内容实体 | 目标、任务、计时会话（含区间与快照） |
| 首次上传 | 已登录用户将本机历史内容上传到当前账户 |
| 换机恢复 | 同一账户在新设备登录后拉取云端内容 |
| 增量同步 | 本地变更上行、云端变更下行 |
| 离线与重试 | 断网可继续用本机；恢复网络后补同步 |
| 冲突处理 | 同一实体两端都改时的确定策略 |
| 删除同步 | 软删除传播到云端与其他设备 |
| 账户注销云端删除 | 注销时删除该账户全部云端内容与授权凭据 |
| 同步状态展示 | 仅在真实同步成功/失败时展示，登录≠同步 |

### 1.2 本增量不包含

- 端到端加密与用户自持密钥
- 多人协作、共享目标
- Widget / Watch / 网页端完整功能
- 历史版本时间旅行 UI（服务端可保留有限审计日志）
- 自动合并同一任务的「双端同时计时」为一条会话（见 §5.4）
- 优先级、日历、标签等非同步相关能力

## 3. 数据归属与账户边界

### 3.1 账户模型（现状约束）

- Apple 与微信登录建立**独立账户**，openid/subject 不合并。
- 会话绑定单一账户；云端内容按 `account_id` 隔离。
- **禁止**把 A 账户的云端内容静默写入 B 账户。

### 3.2 本机内容状态

| 状态 | 含义 | 是否上云 |
| --- | --- | --- |
| `localOnly` | 从未绑定账户，或用户选择「仅保留本机」 | 否，除非用户显式上传 |
| `pendingUpload` | 已绑定账户，等待首次或增量上行 | 是 |
| `synced` | 与云端一致（在已知版本内） | 是 |
| `conflict` | 需要按冲突策略处理 | 按策略合并后上行 |

### 3.3 登录与同步关系（文案口径）

| 事件 | 允许文案 | 禁止文案 |
| --- | --- | --- |
| 仅登录成功 | 「已登录 · 数据仍保存在本机」 | 「备份完成」「已同步」 |
| 同步成功 | 「已同步 · 刚刚」 | 无时间戳的虚假成功 |
| 同步失败 | 「同步失败 · 可重试」+ 保留本机数据 | 「已保存到云端」 |

## 4. 云同步不是备份

| 机制 | 目的 | 是否可省略 |
| --- | --- | --- |
| 云同步 | 多设备内容一致 | 产品能力 |
| **版本化 JSON 导出** | 用户可带走、可归档 | 否 |
| **JSON 导入恢复** | 从导出包重建本机库 | 否 |
| **恢复验证** | 导入后断言实体数量与关系 | 否 |
| 服务端定期备份 + 恢复演练 | 运营级灾备 | 同步正式开放前必须完成 |

### 4.1 导出格式（独立能力，可先于同步交付）

- 单一 JSON 文件，含 `schemaVersion`、导出时间、应用版本。
- 必须完整包含：目标、任务（含 `goalId`、完成/删除时间）、计时会话（含 `taskTitleSnapshot`、目标快照、`activeIntervals`）。
- **CSV 仅用于人读统计，不得作为恢复源。**
- 导入：校验 `schemaVersion` → 预览将新增/跳过数量 → 确认后写入 → **恢复验证**（行数、外键、区间非负）。

### 4.2 验收（导出/恢复）

- [ ] 导出→删除本机数据→导入→任务数、目标关联、计时总时长一致
- [ ] 跨午夜计时导入后统计仍按本地日切分
- [ ] 损坏/截断文件导入失败并给出可读错误，不写半截库
- [ ] 同步开启后导出仍可导出「含未同步变更」的数据

## 5. 同步行为规则

### 5.1 首次绑定账户（D1）

```text
游客有本机数据
  → 选择「上传到此账户」
      → 标记 pendingUpload → 全量上行 → synced
  → 选择「仅保留本机」
      → 保持 localOnly，云端为空；换机不会出现这些数据
```

- 首次上传前必须二次确认数据量（约 N 条任务 / M 段计时）。
- 上传失败可重试；不得部分成功却显示「已同步」。

### 5.2 换机恢复

- 同账户新设备登录且本机为空 → 提示「从云端恢复此账户的数据」→ 确认后拉取。
- 同账户新设备本机已有 `localOnly` 数据 → 按 D1/D2：**不自动合并**；提供「云端恢复」与「保持本机」明确分支。

### 5.3 增量同步

- 以实体为单位携带 `id`、`updatedAt`、`version`（或等价单调版本）。
- 上行：本地变更防抖后推送；失败入队，前台重试。
- 下行：拉取变更列表；应用冲突策略后写入 SwiftData。
- 删除：软删除标记与 `deletedAt` 同步；其他设备列表立即不再展示。

### 5.4 多设备计时（D6/D7）

**不允许**把两台设备上「同一任务的运行中会话」自动合并为一个。

规则：

1. 云端记录「某任务存在活跃计时」的租约（设备 ID + 会话 ID + 开始时间 + 过期时间）。
2. 第二设备对同一任务开始计时：
   - 默认展示：「『任务名』正在其他设备计时」
   - 操作：「查看当前计时」/「仍要开始（独立记录）」/「取消」
3. 若选择独立记录：产生**另一条** `TimingSession`，历史可都保留；目标汇总时长相加。
4. 租约过期（设备离线超过阈值，建议 15 分钟）后允许其他设备接管；接管不改写已产生的历史区间。

### 5.5 离线

- 离线：完整本地功能可用；状态显示「离线 · 有 N 项待同步」。
- 恢复网络：自动补同步；队列按时间序执行。
- 长期离线超过 D9 上限：阻止静默堆积，引导导出。

### 5.6 冲突（D5）

- 粒度：实体级，不提供字段级三方合并 UI。
- 比较：`updatedAt` → 确定性决胜规则 → 服务端接收序。
- 已结束计时会话冲突：保留**更长的有效区间并集**或较新结束时间中**有效总时长较大**者（实现前用测试锁定一种，禁止随机）。
- 冲突解决结果必须写回双方可观测版本，避免来回翻转。

## 6. 注销与删除

### 6.1 注销账户（必须覆盖云端内容）

| 步骤 | 行为 |
| --- | --- |
| 1 | 校验最近 10 分钟内有效登录（沿用现有规则） |
| 2 | 撤销 Apple 授权（若 provider=apple）；微信无 revoke 则仅删本地凭据并提示微信设置 |
| 3 | **删除该账户全部云端内容实体与会话**（不只是 auth 凭据） |
| 4 | 删除账户与所有登录会话 |
| 5 | 本机任务/目标/计时**保留**；状态回到游客或 localOnly |
| 6 | 失败可重试；不得假装成功 |

### 6.2 产品级删除 vs 账户注销

- 单条任务/目标删除：同步软删除，他端消失；云端按 D4 保留期清理。
- 用户误删：同步**不能**当撤销手段；应依赖导出备份或（可选未来）回收站。

## 7. 界面与状态

### 7.1 「我的」页

| 状态 | 展示 |
| --- | --- |
| 游客 | 现有游客提示；**不**写「卸载必丢」的绝对化表述，改为「目前不能保证数据可恢复；建议导出备份」 |
| 已登录·同步中 | 「同步中…」 |
| 已登录·已同步 | 「已同步 · 时间」 |
| 已登录·失败 | 「同步失败」+「重试」；点开可见最近错误类别（网络/登录过期/冲突） |
| 已登录·离线 | 「离线 · N 项待同步」 |

### 7.2 首次绑定与恢复流程

- 必须分步确认，可取消；取消后保持同步关闭。
- 全量上传/恢复进行中可取消；取消后不显示成功。

### 7.3 设置

- 「同步」开关（关闭需确认：「关闭后仅保留本机，云端不再更新」）
- 「导出备份」/「从备份恢复」（独立入口）
- 「同步帮助」说明冲突与多设备计时规则（简短）
